# Studio decisions

- **D-001** Keep Astro 7 static output and Preact islands. Studio is one client-only island at `/studio`, using hash routing.
- **D-002** Voice follow is removed (M1). The pre-removal state is tagged `archive/voice-follow-v1` for possible revival.
- **D-003** Local-first data: IndexedDB for scripts, ideas, takes and settings. No accounts.
- **D-004** Record the camera `MediaStream` directly with `MediaRecorder`. Prefer MP4 (H.264/AAC). No canvas compositing in v1.
- **D-005** Export through the Web Share API with files, falling back to download. No platform publishing APIs.
- **D-006** PWA with a hand-written service worker: network-first HTML, cache-first hashed assets, Studio works offline.
- **D-007** No servers or new infra. Desktop-to-phone handoff uses URL fragments (QR or link). Reminders use `.ics` files. Remote control uses keyboard and Bluetooth keys.
- **D-008** Umami-only product analytics, always on, with a random device id passed to `umami.identify()`. Typed event taxonomy, enum properties only.
- **D-009** SEO is tool-first: landing pages carry a working entry point above the fold. No fabricated volumes. No named comparison pages until the owner verifies them.
- **D-010** Integration branch `codex/creator-studio`. Launch happens via a PR into `main` after M7 and owner device QA.
- **D-011** Studio speed is expressed in WPM. Pixels per second are derived from measured pixels per word.
- **D-012** No new UI frameworks. Dependencies are limited to the list in 0.4.
- **D-013** Same origin `www.teleprompter.wtf` for the site and Studio, so homepage-to-Studio handoff can use shared storage and SEO authority stays in one place.
- **D-014** The classic presenter stays for speakers (P4). Studio reuses its scroll engine.

- **D-015** Until the settings schema and content packs exist in later milestones, seed the analytics allowlists for settings, templates and niches from the approved plan. M5 and M8 must derive or reconcile those lists against their shipped schemas and content IDs so the validation cannot drift.
- **D-016** The plan names `words_bucket` without defining its boundaries. Reuse the classic script-size buckets for now. Use `0` as the session streak bucket before a streak exists. Revisit the boundaries with the Studio data layer and real usage.
- **D-017** Virtual page titles are fixed labels derived from the normalized route rather than arbitrary caller-supplied titles. This preserves the no-user-content analytics rule even if a future caller passes a script title.
- **D-018** In M3, Present hands the editor text to the existing classic presenter through same-origin session storage and opens it immediately. This keeps the classic presenter working before Studio gains its own prompter in M4, and avoids importing the classic site's CSS into the Studio shell. The text stays on the device and is removed from session storage when the presenter opens.
- **D-019** M5 imports the M4 `record.quick` values into the versioned `settings` object only when `settings` is absent. This preserves existing camera, grid, safe zone and countdown choices without maintaining two writable settings sources. All later reads use the sanitized single object.
- **D-020** The transfer codec lives in `src/domain/studio/transfer.ts`, not `handoff.ts` as 11.7 names it. `handoff.ts` already holds the homepage-to-Studio entry point used by content pages, so adding the codec there would pull it into those pages' import graph. M8 can import the same encoder for `S1.` links.
- **D-021** The service worker covers more than 11.8 lists. The parser reads `dist/studio/index.html` and `dist/offline/index.html` because that is what this Astro config emits, and it follows the built module graph because the `client:only` island is referenced by attributes and chunks, not only by `script src` and `modulepreload`. `/fonts/*` is cache-first, and `/site.webmanifest` and `/favicon.svg` are network-first with a cache fallback. Without these, precached files would not be served offline, and a changed manifest with an unchanged precache list would never refresh.
- **D-022** `#/inbox` ships in M6 as a minimal read-only landing, because the share target must land on a real screen before the M8 Ideas inbox exists. `?go=idea` opens it for the same reason. `/share-target` redirects to `?shared=1` only when an idea was stored, to plain `#/inbox` when the share had nothing usable, and to `?shared=error` when storing failed, so the landing never claims a save that did not happen. `captured_idea` is tracked on that landing because a service worker has no Umami. The note "Idea saved." and the failure note are new copy not in Appendix A.
- **D-023** The service worker opens the Studio database without a version number, so a later schema version in the app cannot make a share fail with a `VersionError`. A unit test compares the schema it creates against the app's.
- **D-024** The standalone `persist()` request uses its own key, `storage.persistRequestedStandalone`. The kept-take request already uses `storage.persistRequested`, and Android shares storage between the browser and the installed app, so one key would skip the second request that 11.2 asks for.
- **D-025** Two behaviors go beyond the plan to protect a take and a failed paste. The "Update ready" toast is hidden on the Record screen, because its Reload would end a take. When the clipboard cannot be read, Paste scripts reveals a labelled field for the code, because some browsers refuse `readText`.
- **D-026** `public/_headers` carries no global `Cache-Control`. Hosts that read this file merge every matching rule, which would combine `max-age=0` with the immutable `/_astro/*` rule. The file also cannot express redirects, so the `/share-target` 303 fallback exists only in `nginx.conf`, the production server.
- **D-027** The M7 streak records local calendar date strings at the time a kept take or 80% practice run completes. It recalculates the current run from today's local date on every read, with a one-day allowance for a future date after westward timezone travel, so DST and travel do not rely on elapsed hours as days. It keeps the best run, stores at most 366 dates so transfer codes remain valid, and uses no freezes until M9. Practice advances by elapsed reading time at 140 WPM; its 80% point counts once per nonempty run.
- **D-028** M7 navigation and `llms.txt` link only to live routes. Templates, hooks, record landing pages and new creator guides are still scheduled for M8 and M10, so linking to them now would send visitors and crawlers to 404 pages. Add their planned navigation and discovery links when those pages ship.
- **D-029** A downloaded `.ics` file does not prove the user imported it. Reminder settings now record `fileDownloaded` only, show an import confirmation prompt in Settings, and offer a separate `askEnabled` switch for the Home suggestion. Existing `reminders.enabled` values migrate to `fileDownloaded` because that was the only action the app observed. The app makes no claim that a calendar alert is active.
- **D-030** Practice (9.7) is its own light component that follows Record's regions (prompter under the lens, optional mirrored camera behind it, controls in the thumb zone) rather than a mode of `RecordScreen`, which is entangled with the recorder, permission flow and settings sheet. Progress now advances by words at an adjustable WPM, replacing the fixed 140 WPM timer in D-027, so "average WPM" reports something real. The target fit in the summary projects the pace of the run across the whole script, so a run finished early is still comparable with the target.
- **D-031** Keeping a take removes the script from Up next, since "Record next" would otherwise repeat the same script. Changing the queue does not change `updatedAt`, because queueing is not an edit and must not reorder the library or change "last updated". `#/record/next` opens the head of the queue and falls back to the most recently updated script.
- **D-032** Template pages do not yet link to `/record/*` (13.4), because those pages ship in M10; this extends D-028. Each template links to the previous and next template instead, which gives every template the three contextual inbound links 13.4 asks for without inventing related content. "Record this hook" creates a new script rather than reusing `openInStudio`, which would overwrite the visitor's `quick` script.
- **D-033** Batch mode's 5-second "Next up" card opens Record for the next script but does not start the camera recording. Starting a take on a timer, with no tap, could record someone who has looked away. "End batch" is added so a session can stop early, and the summary and Save all still cover the takes already kept. Batch state lives in `sessionStorage`, since a batch belongs to one sitting and takes are safely stored either way.
- **D-034** Templates and hooks load as lazy chunks, on first use of the picker or inbox. Importing them through `content/studio/index.ts` raised the Studio entry from 47 KB to 105 KB gzip. Both chunks stay in the service worker precache, so the pickers work offline. The barrel stays for Astro pages only.
